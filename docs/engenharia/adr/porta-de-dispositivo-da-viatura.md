# Porta de dispositivo da viatura: o Web Bluetooth vive só no adaptador

A balança e a impressora da viatura entram na app por uma **porta** (`VehicleDevice`: pesa, imprime, identifica-se), injetada no ecrã da paragem `/viatura` — o mesmo padrão da porta `RoadRouter` da API (o domínio nunca fala com o OSRM; aqui, o ecrã nunca fala com GATT). O ecrã e os testes conhecem só a porta; o **falso** (pesos programados, etiquetas «impressas» registadas) serve dev e testes; o Web Bluetooth vive num **único adaptador**, importado a pedido no toque «Ligar», com os tipos mínimos declarados localmente. Outra consequência assumida: o **UUID da etiqueta gera-se no dispositivo** e a API aceita-o (`label_code` em `POST /lots/{code}/units`), para a etiqueta imprimir offline e reconciliar depois pelo código (o QR leva o UUID nu, como o SVG do servidor).

- **Decidido a 17 de novembro de 2026** ([#58](https://github.com/helderpgoncalves/novelo/issues/58), pai [#54](https://github.com/helderpgoncalves/novelo/issues/54)); hardware alvo e alternativa HID em [features §12](../features.md#12-ecrã-da-viatura-pesar-etiquetar-offline) e no branch `research/hardware-viatura`.
- **Alternativas rejeitadas:** SDK nativo Android (uma app fechada para poupar um adaptador — não compensa no MVP); Web Bluetooth espalhado pelo ecrã (impossível de testar sem hardware e acopla a UI ao GATT); etiqueta impressa só com UUID do servidor (partia a impressão offline — o QR do papel tinha de apontar para um código que a API ainda não conhecia).
- **Consequências:** o hardware real (KERN IXC + Zebra ZQ511) prova-se à mão em Android + Chrome, sem testes automáticos de GATT — o que se testa é a porta com o falso (pesos, etiquetas, fila); balanças HID por teclado encaixam na mesma porta (são «leitura manual»); iOS fica de fora por desenho (sem Web Bluetooth nem Background Sync), o que está documentado no ecrã e em [features §12](../features.md#12-ecrã-da-viatura-pesar-etiquetar-offline).
